Thrive auth probe (standalone, zero console code)

Same origin, same values as the console sign-in. It shares no console module. Its one job is to answer, on the device that hangs, a single question: is the CORS preflight (OPTIONS) the thing that hangs?

P2 is the exact shape the console builds (an apikey header + JSON body): a NON-simple request, so the browser sends an OPTIONS preflight before it. P3 is a CORS-simple request (apikey in the query string, text/plain body, no custom header): the browser sends NO preflight. P4 is the official @supabase/supabase-js shape (apikey + Authorization + Content-Type + X-Client-Info): a HEAVIER preflight. Read the result like this: if P3 completes fast while P2/P4 time out, the preflight is the block, and the official client (P4's shape) would hang too. If P2 also completes, the hang is not the request shape. Photograph the summary.
