# NEWMSG_FLOW_TRACE — the current "New message" flow, mapped exactly

**Read-only trace. No behavior changes in this PR — docs only.** This maps the live flow so the rebuild
(direct buttons + a per-file include/exclude upload review) reuses the existing send path and invariants
instead of forking them.

All anchors are `file:line` in the source modules the bundler inlines. `board.html` is generated by
`buildBoard()` in `tools/bundle.js`; the `board-*.src.js` modules are inlined verbatim into the one IIFE
(function declarations hoist, so cross-module calls resolve regardless of order). Line numbers are as of
this branch's base (`main`).

---

## 1. Entry: the "New message" action and the three-option screen (the maze)

### The button and the window

- **Header button** `#newMsgBtn` → `owNewMessage()` — `tools/bundle.js:2025` (wire), `tools/bundle.js:2532` (fn).
- `owNewMessage()` mints a **fresh** opp slug (`nmNewSlug()`), clears any draft pointer, seeds
  `__edBase[slug] = {}`, and calls `openOppWindow(slug, null)` — `tools/bundle.js:2532-2537`.
- `openOppWindow(slug, mode)` sets `__owSlug`, `__owMode = null`, unhides `#owScrim`, calls `owRender()`
  — `tools/bundle.js:2518-2522`.
- `owRender()` with `__owMode === null` paints the **mode selector** (`owModeSelectHtml()`) into `#owBody`
  and hides the tab strip — `tools/bundle.js:2250-2257`.

### The three-option first screen

`owModeSelectHtml()` renders three `.ow-mode-btn` cards — `tools/bundle.js:2232-2242`
(labels/subs: `ow_new_text*` / `ow_new_upload*` / `ow_new_pick*`, `tools/bundle.js:1516-1518`, AR `:1627-1629`):

| Button (id) | Handler wired | Calls | Lands on |
|---|---|---|---|
| **Text message only** (`#owPickText`) | `tools/bundle.js:2253` | `owSelectMode("a")` | Mode **A** — lean compose |
| **Upload a page or campaign** (`#owPickUpload`) | `tools/bundle.js:2254` | `owSelectMode("upload")` | Mode **B**, Page tab, path `upload` pre-selected |
| **Pick from the Library** (`#owPickLib`) | `tools/bundle.js:2255` | `owSelectMode("pick")` | Mode **B**, Page tab, path `pick` pre-selected |

`owSelectMode(mode)` — `tools/bundle.js:2276-2281`:
- `"a"` → `__owMode="a"`, `__owTab="msg"` → `owRender()` mounts Mode A (`owModeAMount`) — `:2264-2266`.
- `"upload"` / `"pick"` → sets `__owStartPath = mode`, `__owTab="page"`, `__owMode="b"` → `owRender()`
  mounts **Mode B** — `:2277-2278`, `:2267-2269`.

### Where the maze is

The first screen promises three direct choices, but **Upload** and **Pick** do **not** go straight to a
file picker or a template list. They both open the **full Mode B tabbed campaign editor**:

1. `owRender()` mode `"b"` paints the **4-tab strip** (Message / Page / Recipients / Preview) plus a
   footer **Commit** button — `owTabsHtml()` `tools/bundle.js:2287-2289`, `owModeBBodyHtml()` `:2290-2297`.
2. `owModeBMount(slug)` mounts the Message tab (`owMsgMount`) **and** the Page tab (`owPageMount`), wires
   the footer `#owCommit` → `owCommitCampaign(slug)`, then, because `__owStartPath` is set, switches to the
   Page tab and calls `owSelectPath(__owStartPath)` — `tools/bundle.js:2309-2318`.
3. **The Page tab re-presents its own two path buttons** (`owPathUpload` / `owPathPick`) via `owPageMount`
   — `tools/board-upload.src.js:1407-1424`. So a second layer of the same choice exists under the first
   screen: the first-screen "Upload"/"Pick" is really a shortcut that auto-clicks one of these two Page-tab
   path buttons (`owSelectPath` at `:1315`).

So the redundant layers a rebuild collapses: **(first screen: 3 options) → (Mode B: a 4-tab campaign
editor) → (Page tab: 2 path buttons again) → (a separate footer Commit distinct from the Message-tab
Send)**. Only "Text only" is already direct (straight to Mode A compose + `#nmSend`).

## 2. Path 1 — Text message only

- `#owPickText` → `owSelectMode("a")` → `owRender()` → `owModeAMount(slug)` — `tools/bundle.js:2264-2266`.
- `owModeAMount(slug)` paints `composeBodyHtml(slug,row,detail)` into `#owModeA`, then re-paints after
  `oppReadData` prefill; wires via `owModeAWire → nmWire` — `tools/board-newmsg.src.js:130-141`.
- **Fields** come from `composeBodyHtml` = `composeFieldsHtml` + the Send bar (`#nmSend` + `#nmStatus`) —
  `tools/board-newmsg.src.js:87-91`. `composeFieldsHtml` = `editorHtml` (subject `#edSubj` + body `#edBody`
  + signature `#edSig` + the `#edPreview` srcdoc) + `greetingHtml` (greeting toggle + smart-name +
  platform) + `recipientHtml` (`#recIn`) + `bulkHtml` — `tools/board-newmsg.src.js:80-85`.
- **Wiring** `nmWire(slug)` — `tools/board-newmsg.src.js:192-199`: fields via `wireEditor`; recipient input;
  `#nmClose`; and **`#nmSend` → `unifiedSend(slug)`** (`:197`). Live gate: `nmTick → sendApplyGate` enables
  Send only when subject + body + a valid recipient exist — `:150-157`.
- **Autosave** (debounced): `nmScheduleSave → nmSaveNow` writes subject/body/signature/recipients/greeting
  to the opp — `tools/board-newmsg.src.js:159-188`.
- **Reaches the send path** at `#nmSend` → `unifiedSend(slug)` (see §5). No page/campaign/library machinery
  on this path — it is the lean compose.

## 3. Path 2 — Upload a page or campaign

### Reaching the input

`#owPickUpload` → `owSelectMode("upload")` → Mode B → `owModeBMount` → `owTabTo("page")` +
`owSelectPath("upload")` — `tools/bundle.js:2313-2316`. `owSelectPath("upload")` highlights the upload path
button, reveals `#owBodyUpload`, hides the pick body, and **resets `__upPlan` and the review** —
`tools/board-upload.src.js:1348-1357`.

### The OS file picker

The Page tab renders a hidden native file input inside a styled label — the label is what the operator taps,
which opens the OS picker:
`<label class="act ow-up-btn">…<input type="file" id="owUploadFile" accept=".zip,.html,.htm" hidden></label>`
— `tools/board-upload.src.js:1412-1414`. Its `change` handler → `owCampaignOnFile(uf.files)` —
`tools/board-upload.src.js:1425`.

### Single page vs multi-file/zip — parse & plan

`owCampaignOnFile(files)` — `tools/board-upload.src.js:1362-1372`:
1. `upBuildPlan(files)` (the unified parse) + `owPageLoadExisting()` in parallel.
2. `upBuildPlan(files)` — `tools/board-upload.src.js:217-…`: reads every file (`upReadFiles`), turns HTML
   files into **page rows**, parses text/markdown into **message units** (`upParseSections`/`upExtract`),
   then **folder-first pairs** each page with the message that shares its subfolder (the per-slug zip
   `bards-alley/index.html` + `bards-alley/<name>.md`), falling back to a token ranker — `:223-256+`. A
   single `.html`/`.htm` yields **one** row; a `.zip` yields **N** rows (one per page).
3. Back in `owCampaignOnFile`: **a single page (`rows.length===1`) defaults its slug to the opp's own slug**
   (`rows[0].slug = __owSlug`) — `:1368`; a multi-page zip keeps each page's derived slug. The **whole plan**
   is held on `__upPlan` (never `rows[0]`) — `:1369`. Then `owCampaignRenderReview()`.

### Where the review renders — rendered srcdoc, not raw text

`owCampaignRenderReview()` — `tools/board-upload.src.js:1384-1398`: for **every** row it renders
`owCampMetaHtml(r)` (matched recipient + subject, read-only) + `libRowHtml(r,i)` into `#owPageReview`, then
wires each row's inputs to `libCollectRows` (the shared per-row validation). `libRowHtml(r,i)` —
`tools/board-upload.src.js:729-745` — shows editable **Title/Slug/Task** inputs, a per-row error slot
(`#libErr-i`), and a **rendered page preview via `pageFrameIframe(r.page.html)`** (a sandboxed `srcdoc`
iframe — the real page, not a source-text snippet) — `:741-743`, `pageFrameIframe` at `:538`.

> **No per-file include/exclude today.** The only per-row controls are edit (title/slug/task). Every row in
> the plan is committed; there is no checkbox to drop one file from a multi-page upload. This is the gap the
> rebuild adds.

### The exact commit point — all-or-nothing

Footer **Commit** `#owCommit` → `owCommitCampaign(slug)` — wired at `tools/bundle.js:2312`.
`owCommitCampaign(slug)` **routes by row count** — `tools/board-upload.src.js:1435-1465`:
- **`rows.length > 1`** → `owCommitCampaignAll(slug)` — `:1440`.
- **`rows.length === 1`** (single page or picked template) → commit **one** card using the interactively
  written Message-tab subject/body; validated by `libCollectRows(true)` (`:1446`); B2 strip
  (`sendToList().filter(!isSuppressed)`, `:1449`); `{{ASSET_BASE}}` resolved (`assetBaseInto(pr.page.html)`,
  `:1448`); `oppUpsert` + `pageUpsert` + `pagePublishRelay` (`:1454-1456`); F1 publish-truth via
  `upActivateBackground` (`:1458`).

`owCommitCampaignAll(slug)` — `tools/board-upload.src.js:1472-1493`: `libCollectRows(true)` gates **all**
rows (`:1476`); on pass, delegates to **`upCommit(plan)`** — the same multi-row commit the standalone
upload uses (`oppUpsert` + `pageUpsert` + `pagePublishRelay` per row, B2 strip and `{{ASSET_BASE}}` inside
`upCommit`) — `:1478`; F1 via `upActivateBackground(res.published)` (`:1479`); partial failures are **named**
but the commit is otherwise a single all-rows operation (`:1483-1489`). **There is no per-row exclude before
this call** — the plan commits in full (a row can only be dropped by fixing/renaming it to pass validation,
not by opting it out).

## 4. Path 3 — Pick from the Library

- `#owPickLib` → `owSelectMode("pick")` → Mode B → `owModeBMount` → `owTabTo("page")` +
  `owSelectPath("pick")` — `tools/bundle.js:2313-2316`; `owSelectPath("pick")` reveals `#owBodyPick` and
  lazily loads the list via `owPagePickList()` — `tools/board-upload.src.js:1348-1357`.
- **Browse:** `owPagePickList()` — `tools/board-upload.src.js:1312-1328` — calls `owPageLoadExisting()`
  (`:1280-1286`) → **`libFetchPages()`** = `restGet("console_pages?select=slug,title,task,live_verified_at,
  up,updated_at&order=up.desc")` — `tools/board-upload.src.js:937-940`. Renders `.ow-pick-row` rows with a
  search box (`#owPickSearch` → filter, `:1426`), each row offering **Use** (`data-ow-pick`) and
  **Duplicate** (`data-ow-dup`) — `:1318-1326`.
- **Pick → review:** `owPagePick(slug, duplicate)` — `tools/board-upload.src.js:1329-1338` — reads the
  stored html via `pageReadHtml(slug)` and calls `owPageSetReview({ slug: duplicate ? "" : __owSlug, … })`.
  `owPageSetReview(row)` holds it as a single-row `__upPlan` and renders the **same** `libRowHtml` review
  (rendered srcdoc) — `tools/board-upload.src.js:1289-1298`. **Use** copies the template's html to *this*
  campaign at the opp's slug; **Duplicate** forces a fresh slug the operator names.
- **Becomes a card / opens in Operations:** the operator writes the message on the **Message tab** (shared
  `owMsgMount`, §5 fields) and presses **Commit** → `owCommitCampaign(slug)` → the single-row branch
  (§3), which `oppUpsert`s the opp (a board card) + `pageUpsert`/`pagePublishRelay` the page, then
  `reloadBoardData()` surfaces the card on the board. (The Library surface's own separate "Promote" action
  exists too — `libPromote*` — but the New-message Path 3 is the pick→review→Commit route above.)

## 5. Shared send path — the single convergence, and where each invariant lives

### The single path

- **Interactive send** (Path 1 text-only, and the Message gate / Mode A) converges on
  **`#nmSend` → `unifiedSend(slug)` → `runSend(slug)`**:
  - `unifiedSend(slug)` — `tools/board-newmsg.src.js:244-272`: validates subject+body (`:247`) and at least
    one recipient (`:248`); persists subject/body/**signature**/recipients/**greeting**/platform to the opp
    (`oppUpsert`, `:252-254`); `reloadBoardData()` so `runSend`'s `findRow` resolves (`:256`); then
    `runSend(slug)` (`:261`) and surfaces the one result string in `#nmStatus` (`:262-264`).
  - `runSend(slug)` — `tools/board-send.src.js:507-584` — the UNCHANGED L5 group send (optimistic paint →
    per-recipient relay → `console_mail` write on acceptance).
- **Campaign Commit** (Paths 2 & 3) writes the opp + page and lands a **card**; the card's later send also
  goes through `runSend` (from the board card / control-room MESSAGE gate `#nmSend` → `unifiedSend`). So
  **`unifiedSend → runSend` is the one send path all surfaces reach**; Commit does not send email itself —
  it publishes the page and creates the card, and the message is sent through `runSend`.
