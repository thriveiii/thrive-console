# EDITOR_TRACE.md

READ-ONLY trace for E0 (editor / drawer, evidence for the THREE_SURFACES_ONE_WINDOW port). No code, no
design, no PR. Every claim is cited `file:line` on origin/main (`358c690`).

## How the board shell is actually built (read this first)

The live shell `library/board.html` is not authored by hand and is not a plain concatenation of the
`tools/board-*.src.js` sources. It is GENERATED by `buildBoard()` in the bundler (`tools/bundle.js:892`),
which INLINES the six `board-*.src.js` sources into one IIFE (`tools/bundle.js:896-910`) and wraps them in a
hand-written template that carries the shell chrome: the `<head>`/CSS, the overlay container markup, and the
drawer's own open / close / wire / assemble functions. So:

- The DRAWER itself (container markup, width/position CSS, `openDrawer` / `closeDrawer` / `wireDrawer` /
  `drawerHtml` / `refreshDrawer`, and the card trigger) lives INLINE in `buildBoard` (`tools/bundle.js`), not
  in any `board-*.src.js`. The rendered mirror is `library/board.html` (cited where useful).
- The COMPOSER, PREVIEW, RECIPIENT and PAGE sections the drawer stitches together are the `board-*.src.js`
  sources.

Board.html's ACTUAL names ARE `drawerHtml` / `openDrawer` / `wireDrawer` / `closeDrawer` / `refreshDrawer`
(`tools/bundle.js:1872,1895,1880,1913,1922`) - the same family app.js uses, but defined here inline in the
bundler, NOT imported from app.js. app.js is not cited as authority.

The settled centered window this port targets already exists in the OTHER shell (`library/console.html` /
`library/app.html`, built from `library/*.html` + app.js): the `#modal` centered dialog with a six-tab strip
(Overview / Text / Page / Outreach / History / Discussion), authored as the `MODAL` template
(`tools/bundle.js:182-218`, tabs at `:203-208`). That is the THREE_SURFACES_ONE_WINDOW shape to bring into
board.html. It does NOT exist in board.html today.

## 1. SIDE PANEL (what E-3 retires)

- **Container markup.** One overlay per surface, all sharing `.scrim` + `.drawer`. The opp drawer is
  `<div id="scrim" class="scrim" hidden><div id="drawer" class="drawer" role="dialog" aria-modal="true">`
  (`tools/bundle.js:1176`; rendered mirror `library/board.html:265`). The profile / admin / new-message /
  upload overlays reuse the same `.drawer` class (`tools/bundle.js:1177-1180`).
- **Actual open / close / wire names.**
  - `drawerHtml(row, detail)` - the body ASSEMBLER (`tools/bundle.js:1872-1878`).
  - `openDrawer(slug)` - mounts `drawerHtml` into `#drawer`, unhides `#scrim`, wires, then enriches via
    `fetchDetail` and re-renders (`tools/bundle.js:1895-1912`).
  - `closeDrawer()` - clears `__drawerSlug`, hides `#scrim` (`tools/bundle.js:1913`).
  - `wireDrawer()` - binds close, the `.act[data-act]` buttons, note add, recipient save/input, `wireEditor`,
    `upWireActivate` (`tools/bundle.js:1880-1894`).
  - `refreshDrawer(slug)` - re-open in place after a write (`tools/bundle.js:1922`). State flag
    `__drawerSlug` (`tools/bundle.js:1879`).
- **How a board card triggers it.** Each `.card[data-slug]` gets a click and an Enter/Space keydown that call
  `openDrawer(slug)` (`tools/bundle.js:2111-2114`). Dismissal is wired once: a backdrop tap
  (`e.target===s`) and Escape both call `closeDrawer()` (`tools/bundle.js:2159,2170`).
- **Width / position CSS.** `.scrim{position:fixed;inset:0;...display:flex;justify-content:flex-end}`
  (`tools/bundle.js:989`), flipped for RTL by `html[dir="rtl"] .scrim{justify-content:flex-start}`
  (`tools/bundle.js:991`); `.drawer{width:min(480px,100%);height:100%;background:#0b0b11;
  border-inline-start:1px solid #1c1c26;overflow-y:auto;padding:16px 16px 48px}` (`tools/bundle.js:992`).
  This is the edge-pinned 480px side panel E-3 retires (the port replaces the `justify-content:flex-end` +
  `border-inline-start` edge dock with a centered window).

## 2. COMPOSER (subject / body / recipient / signature)

The composer nodes are DEFINED ONCE, in `editorHtml` (`tools/board-editor.src.js:113-147`) and `recipientHtml`
(`tools/board-recipient.src.js:55-68`), and MOUNTED in two surfaces: the drawer, via `drawerHtml`
(`tools/bundle.js:1877`), and the standalone New-message overlay `#nmScrim`/`#nmPanel`, via `nmPanelHtml`
(`tools/board-newmsg.src.js:73-84`). One definition, two mount points (`edRoot()` scopes reads to the active
one, `tools/board-editor.src.js:79-84`).

- **Subject:** `#edSubj` text input (`tools/board-editor.src.js:129`).
- **Body:** `#edBody` textarea (`tools/board-editor.src.js:131`).
- **Signature:** `#edSig` textarea (`tools/board-editor.src.js:141`), with the "Use my signature" fill button
  `#edSigFill` (`tools/board-editor.src.js:140`, handler `edFillSignature` `:202`).
- **Recipient:** `#recIn` textarea (`tools/board-recipient.src.js:64`) plus a Save button `#recSave`
  (`:66`); the SAME `#recIn` is mounted by the overlay too (`tools/board-newmsg.src.js:80`).
- **Send control:** the overlay's `#nmSend` (`tools/board-newmsg.src.js:81`); the drawer's board Send is the
  actions-row button `#drawer .act[data-act="send"]`. Both are toggled by the one shared gate `sendApplyGate`
  -> `sendReady` = subject AND body AND recipient (`tools/board-newmsg.src.js:91-96`).
- **Checklist + status:** `.ed-checks` with `ckSubj`/`ckBody`/`ckRecip`/`ckLink`
  (`tools/board-editor.src.js:134-137`); status lines `#edStatus` (`:146`) and `#nmStatus`
  (`tools/board-newmsg.src.js:82`).

## 3. PREVIEW (the exact-send preview) - this is E-1

- **There is NO `buildOppPreview` in the board sources** (grep of `tools/` for `buildOppPreview`: zero). The
  real equivalent is `edRenderPreview(slug)` (`tools/board-editor.src.js:170-175`): it compiles the live
  subject/body/signature through `edCompileFrom` -> the SEND PATH's own `sendCompile`
  (`tools/board-editor.src.js:105-109`, comment `:22`, `:167-169`), so the preview HTML is byte-identical to
  what `runSend` would POST.
- **What it renders and WHERE.** It sets the `srcdoc` of a sandboxed iframe `#edPreview`
  (`tools/board-editor.src.js:173`), which `editorHtml` mounts INSIDE the editor section, under the label
  `ed_preview` = "معاينة (ما سيُرسل تمامًا)" (`tools/board-editor.src.js:144-145`, i18n
  `tools/bundle.js:1328`). It renders the compiled light-HTML email (the message body, resolved link, and
  signature).
- **Correction to the brief's premise.** In the board shell the exact-send MESSAGE preview is ALREADY shown
  inside the editor - it is the `#edPreview` iframe (`tools/board-editor.src.js:145`), recompiled on every
  keystroke by `edTick` -> `edRenderPreview` (`:176`). So E-1's "embed the send preview in the editor" is
  already satisfied here; the port only needs to carry the existing `#edPreview` iframe into the Text tab. (The
  thing that is NOT in the editor is a full hosted-PAGE preview - that is the Page tab, section 4.)

## 4. INSERT-LINK + PAGE - this is E-2

- **Insert-link bar.** The button is `#edLink` (`tools/board-editor.src.js:133`, label `ed_link` = "إدراج
  رابط الفرصة", i18n `tools/bundle.js:1327`); its handler `edInsertLink` (`tools/board-editor.src.js:183-197`)
  inserts the merge token `MF_LINK` = `{{LINK}}` (or a markdown anchor `[selected]({{LINK}})` around a
  selection). `MF_LINK` is defined at `tools/board-send.src.js:75` and resolved by the compiler
  (`tools/board-send.src.js:81`) to `ctx.link` = `liveUrl(pageSlug)` (`:212`) =
  `https://console.thriveiii.com/opp/<slug>` (`liveUrl` `:33`; `SITE_L5`/`OPP_PATH_L5` `:18-19`).
- **What inserting the link requires today.** Nothing external and NO Library trip: it is a pure token
  insertion into `#edBody`, resolved to the opp's own page URL only at send-compile time. The token needs no
  page to exist and no navigation.
- **The hosted-page iframe preview is NOT in the drawer.** The drawer's page node is `uploadActivateHtml`
  (`tools/board-upload.src.js:591-612`), which renders `.dw-sec.up-act-sec` as a PASSIVE state line `#upState`
  (live / dead / checking / publishing, `:609`) plus an optional Re-check button `#upReverify` (`:610`) - no
  Open, no Copy, no preview (confirmed by the note "the drawer's page section is a passive state line only",
  `tools/board-upload.src.js:645-646`).
- **Opening / copying / previewing the page forces a trip to the Library.** Those controls exist ONLY on the
  Library surface (`#libViewScrim` / `.lvpanel`): `libOpenPage` opens `liveUrl` in a new tab
  (`tools/board-upload.src.js:836`), `libCopyLink` copies it (`:831`), and the on-demand hosted-page preview
  is the sandboxed iframe `.lv-frame` (`:1065`); the upload Done panel also carries Copy/Open (`:810`). None
  of these is reachable from the opp drawer. That separation is the E-2 gap the Page tab closes.

## 5. TABS

- **board.html has NO opp tab strip.** The opp opens as the single-column `.drawer`, and `drawerHtml` stacks
  every section vertically in one scroll: nums, facts, archived-info, editor, page (up-act-sec), recipient,
  actions, thread, record, notes, activity (`tools/bundle.js:1877`). There is no `role="tablist"`, no
  `aria-selected`, no tab on the opp anywhere in board.html.
- **The only tab strip in the whole board shell is the LIBRARY view's**, a SEPARATE surface (`#libViewScrim` /
  `.lvpanel`), not the opp: `.lv-tabs` / `.lv-tab` (CSS `tools/bundle.js:1090-1091`; markup
  `tools/board-upload.src.js:896-898`) with two tabs - Templates (`#lvTabTpl`, `lib_tab_templates`) and
  Archive (`#lvTabArch`, `lib_tab_archive`).
- The settled six-tab centered window (Overview / Text / Page / Outreach / History / Discussion) is present
  only in the console.html/app.html shell, as the `MODAL` template `#modal` / `#modalTabs`
  (`tools/bundle.js:182-218`, tabs `:203-208`). It is the port target, not part of board.html.

## ABSENT (verified missing in board.html)

1. **No centered `#oppWindow` / `#modal`.** The opp opens only as the edge-pinned `.drawer`
   (`tools/bundle.js:992`); no centered dialog markup or CSS exists in `buildBoard`.
2. **No opp tab strip / tablist.** The drawer is one scrolling column (`tools/bundle.js:1877`); the only
   `role="tablist"` in board.html is absent (the Library `.lv-tabs` is a plain button pair, not `role=tab`).
3. **No hosted-page preview or Open/Copy-link control inside the opp drawer.** The drawer page section is a
   passive state line (`tools/board-upload.src.js:591-612`); Open/Copy/preview are Library-only (`:831-836`,
   `:1065`).
4. **No `buildOppPreview` function.** The send-exact preview equivalent is `edRenderPreview` /
   `edCompileFrom` (`tools/board-editor.src.js:170-175,105-109`).
5. **(Not absent - correcting the brief.)** The exact-send MESSAGE preview IS already embedded in the editor
   as the `#edPreview` iframe (`tools/board-editor.src.js:145`).
